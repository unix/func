func project setup for coding agents

Use this guide when the user asks you to create a new func CLI project. Repository instructions and explicit user requirements take precedence.

func is a decorator-based TypeScript framework for command-line applications. The official creator generates the current recommended application, feature-module, custom-decorator, and testing structure. Start from that template instead of assembling a project from remembered APIs.

1. Inspect the target repository

- Read its agent instructions, package.json files, lockfiles, workspace configuration, runtime-version files, and ignore rules before changing anything.
- Preserve the repository's package manager and naming conventions. Inside a monorepo, put the CLI in the normal workspace location as a self-contained package and confirm that the workspace patterns include it.
- For a standalone request, create one new project directory. Never merge generated files into an unrelated application package and never overwrite an existing target directory.

2. Prepare the environment

- func requires Node.js 24.15.0 or newer. Inspect the installed version yourself. Do not make the user run a preliminary environment-check command for you.
- If Node.js is missing or too old, prefer the repository's declared version manager. Otherwise use an existing mise, asdf, nvm, or Volta installation, then the platform's standard package manager or the official Node.js distribution. Install a supported active LTS release and avoid sudo-based global installs.
- Use package.json#packageManager, the lockfile, and workspace configuration to select npm, pnpm, Yarn, or Bun. Activate or install the declared package-manager version when necessary; do not introduce a second lockfile.
- Install only the environment and project dependencies needed for the requested project. Ask the user only when permissions, network policy, or a required system change prevents completion.

3. Create the project

Choose a valid, explicit project name and pass it as the final positional argument. Use the repository's package manager:

- npm: npm init func@latest <project-name>
- pnpm: pnpm create func <project-name>
- Yarn: yarn create func <project-name>
- Bun: bun create func <project-name>

The creator downloads the official TypeScript template, creates a new directory, and rewrites package metadata and package.json#bin for the project name. It intentionally refuses to replace an existing directory.

4. Install and inspect

- Enter the generated directory and install dependencies with the selected package manager.
- Read the generated README, package.json, src, tests, TypeScript configuration, and Vitest configuration before editing them.
- Preserve the generated boundaries: src/index.ts creates the application with createApp(AppModule) and calls app.bootstrap(); src/app.module.ts composes feature modules; each generated command feature owns its command, module, and injectable service; reusable value decorators live under src/decorators; shared providers are exported by a shared module.
- Do not replace createApp/app.bootstrap with an older run-style entry, invent @Service, or flatten the generated feature modules into registry barrel files.

5. Implement only the requested behavior

- Follow https://func.witt.im/rules.txt for commands, services, custom decorators, project structure, output, and tests.
- Use the generated examples as local API evidence. When a requested capability is not demonstrated there, read the relevant Markdown documentation before editing.
- Keep package scripts, func.entry, func.outDir, and package.json#bin aligned. Use funcgo setup as a read-only configuration check for an existing hand-written package; review its output before considering funcgo setup --fix.

6. Verify the new project

- Run the generated dev script with --help, using the selected package manager's normal argument-forwarding syntax.
- Run one representative generated command, such as greet --name Ada, and verify its exit behavior and output.
- Run the default test script. These command tests use func/testing in memory and do not require a build.
- Run the repository's formatter and linter when available. Build only when the user requests a distributable artifact or when running the separate built-CLI test script is part of the requested verification.
- Report the created directory, package manager, any environment dependency installed, commands actually run, and their results. Do not claim checks that were not executed.
