export const serviceCode = [
  "import { text } from '@clack/prompts'",
  "import { Context, Injectable } from 'func'",
  "import type { Readable, Writable } from 'node:stream'",
  '',
  '@Injectable()',
  'export class ClackService {',
  '  static IsTTY(stream: Readable | Writable): boolean {',
  "    return 'isTTY' in stream && stream.isTTY === true",
  '  }',
  '',
  '  constructor(private readonly context: Context) {}',
  '',
  '  projectName() {',
  '    const { stdin, stderr } = this.context.io',
  '    if (!ClackService.IsTTY(stdin) || !ClackService.IsTTY(stderr)) {',
  "      throw new TypeError('Interactive input requires a terminal.')",
  '    }',
  '',
  '    return text({',
  "      message: 'Project name',",
  '      input: stdin,',
  '      output: stderr,',
  '      signal: this.context.signal,',
  '    })',
  '  }',
  '}',
].join('\n')

func does not select or wrap a terminal UI library. Install the library that fits the application and bind it to the current `Context`. This page uses several open-source libraries to demonstrate different integration boundaries; `@clack/prompts` is one example, not a default recommendation.

A terminal UI library treats `output` like a UI render target. Prompts, spinners, cursor movement, and other frames belong on stderr; stdout remains the data channel for final text, JSON, and shell pipelines. Rendering UI to stdout is equivalent to writing a debug overlay into an API response.

## Render a terminal application with Ink

[Ink](https://github.com/vadimdemedes/ink) is a React renderer. Give it invocation-scoped streams, but use stderr as its render target so stdout stays machine-readable. Disable `exitOnCtrlC` and `patchConsole` because func owns signal handling and application output:

<CodeBlock code={inkCode} lang="ts" />

Unmount on every path, and let `Context.signal` unmount early when the command is cancelled. The copyable [Ink service](https://github.com/unix/func/blob/main/snippets/ink.service.ts) includes that signal binding.

## Give stdin one owner with Inquirer

[Inquirer](https://github.com/SBoudrias/Inquirer.js) accepts runtime streams and an abort signal separately from prompt options:

<CodeBlock code={inquirerCode} lang="ts" />

Check that both input and render streams are TTYs before prompting. In CI, a shell pipeline, or another non-interactive environment, use command options or defaults and fail fast when required data is missing. Do not consume the same stdin as both piped application data and interactive key input. See the copyable [Inquirer service](https://github.com/unix/func/blob/main/snippets/inquirer.service.ts).

Awaiting a prompt suspends the command until input arrives; it does not block the Node.js event loop. Synchronous work still blocks input, signal handling, and all terminal animations.

## Clean up progress rendering with Ora

[Ora](https://github.com/sindresorhus/ora) renders a single spinner to a writable stream. Bind that stream to stderr and stop it in `finally`:

<CodeBlock code={oraCode} lang="ts" />

Ora's `discardStdin` feature operates on the process-wide stdin rather than a supplied stream, so disable it when streams are owned by `Context`. The operation itself should accept `Context.signal`. See the copyable [Ora service](https://github.com/unix/func/blob/main/snippets/ora.service.ts).

## Style at the output boundary with Chalk

[Chalk](https://github.com/chalk/chalk) produces styled strings; it does not decide which application channel owns them. Choose color support for the target stream, write decorative or diagnostic text to stderr, and keep structured stdout unstyled:

<CodeBlock code={chalkCode} lang="ts" />

Custom and captured streams should default to color level `0` unless their terminal capability is known. See the copyable [Chalk service](https://github.com/unix/func/blob/main/snippets/chalk.service.ts).
