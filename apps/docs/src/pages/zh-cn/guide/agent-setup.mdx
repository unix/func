下面的任务覆盖项目创建、日常功能开发、结构整理和测试。Agent 组件会将完整提示词发送给所选应用，你也可以复制提示词并按项目需求修改。

## 创建一个新的 `func` 项目

### 适合的场景

这个场景适合第一次使用 `func` 的开发者，也适合希望在现有 monorepo 中快速建立独立 CLI package 的团队。只需要在编码 Agent 中打开目标仓库，无需手动逐项检查 Node.js、包管理器或 workspace 配置。

<AgentTask
  description="在当前仓库创建并验证固定名为 func-example 的可运行项目。"
  locale="zh-cn"
  prompt={createPrompt}
  title="让 Agent 创建 Func 项目"
/>

## 常见开发场景

### 适合的场景

这个场景适合已经可以运行的 `func` 项目。把预期调用方式、必填字段、条件分支和测试要求写清楚，Agent 就可以按现有结构完成标准开发。下面两个任务以 `ship create` 为例，可以直接使用，也可以替换成自己的命令和业务行为。

<AgentTask
  description="添加 ship create --file document.txt，并将 file 声明为必填文件路径。"
  locale="zh-cn"
  prompt={addCommandPrompt}
  title="让 Agent 添加 create 命令"
/>

<AgentTask
  description="为 create 命令添加 --ensure，只有显式启用时才执行文件写入。"
  locale="zh-cn"
  prompt={addEnsurePrompt}
  title="让 Agent 添加 --ensure 选项"
/>

## 优化已有 `func` 项目结构

### 适合的场景

这个场景面向已经维护 `func` 项目的开发者。当命令越来越多、处理器中混入大量业务逻辑，或源码与生成产物混在一起时， 可以让 Agent 在不改变 CLI 行为的前提下整理结构。

<AgentTask
  description="保持命令行为和输出不变，重新整理入口、模块、命令与服务的职责。"
  locale="zh-cn"
  prompt={structurePrompt}
  title="让 Agent 优化 Func 项目结构"
/>

## 为命令补充测试用例

### 适合的场景

这个场景适合正在增加命令、准备发布版本或完成结构调整的维护者。它关注你的 CLI 向使用者承诺的行为，而不是重新测试 `func` 框架内部实现，因此也适合作为团队合并代码前的回归保护。
