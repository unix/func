`func` 框架内用户一般不用关心具体调用在做什么，仅跟随应用架构声明具体的命令与 provider 即可完成工作。当你理解设计模型后，几乎不需要深入底层，这与开发常见的 Web 应用没有什么区别。

在开发者完成命令声明后，框架会通过反射获取元信息并编译命令图。每当用户运行脚本唤起时，`func` 就从命令图中选择唯一匹配的命令节点与处理器，并把用户提供的上下文数据传递给处理器。这些数据在到达处理器之前会经过预先声明的类型转换、校验和约束。

## 定义与调用

Command 是最基础的单元，通常一个工程中包含多个 Command 类，这些类是命令运行的入口。

`@Module()` 定义应用装配边界，注册命令、模块选项和 provider。命令图负责解释 CLI 输入并选择动作；provider 提供可复用的业务能力。每次调用只会从已注册的命令中选择一条执行路径，而不会依次运行多个命令类。

## Command 类型

命令节点是本次调用最终归属的路径。具名命令可以声明一段或多段 path，处理器 path 会继续追加在命令 path 之后。func 还有主命令与缺失命令两种特殊入口；未注册时，对应输入不会凭空创建默认处理器：

| 命令入口 | 选择条件                                            | func API                    |
| -------- | --------------------------------------------------- | --------------------------- |
| 主命令   | 没有匹配具名路径，可执行其默认或 path handler       | `@CommandMajor()`           |
| 具名命令 | 位置 token 最长匹配 command path 与 handler path    | `@Command('<name>')`        |
| 缺失命令 | 位置 token 无法匹配具名路径，并且仍有未消费位置输入 | `@CommandMissing()（可选）` |

<Callout locale="zh-cn" title="命令路径可以共享前缀" variant="decision">

对于 `ship project member add`，可以用 `@Command('project')` 加 `@Handler(['member', 'add'])` 建模，也可以由另一个类声明 `@Command(['project', 'member'])`。func 会编译一棵命令图，并选择最长且唯一的可执行节点。

</Callout>

## 一个命令节点只执行一个处理器

处理器是命令类中执行具体动作的方法，由 `@Handler()` 声明。一个命令类可以提供三种动作入口：

- **默认处理器**没有路径或标志，在当前命令节点没有选择其他动作时执行；
- **路径处理器**使用一段固定的位置 token 扩展命令路径，例如 `member add`；
- **标志处理器**使用 `--version` 一类选项切换到互斥动作。

模块级 `@OptionCommand()` 也可以提供 `--help` 一类跨命令动作。无论声明了多少入口，一次调用最终只执行其中一个。精确选择顺序见[深入了解运行时](/zh-cn/runtime)。

<Callout locale="zh-cn" title="相同表面语法可以承担不同职责" variant="decision">

`@Flag()` 声明的 `--force` 向已经选中的动作提供布尔数据；`@Handler({ flag: 'version' })` 或 `@OptionCommand({ name: 'help' })` 则选择另一个动作。它们都以连字符开头，但职责不同。

</Callout>
