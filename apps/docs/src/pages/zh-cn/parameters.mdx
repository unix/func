  '',

  'export class StatusCommand {',
  '  constructor(@Inject(API_URL) private readonly apiUrl: string) {}',

  '@Module({',

func 有两条明确区分的参数路径：`@Args()` 向当前 handler 提供调用数据；构造函数和 handler 的依赖则通过 DI 解析。

## 使用 Args 读取当前调用

`@Args()` 只能用于 command handler 参数。运行时在完成 command 选择与 option 绑定后才创建它，避免应用启动阶段出现只初始化了一部分的参数对象。

<CodeBlock code={argsCode} filename="src/commands/config.command.ts" lang="ts" />

| 字段          | 包含内容                                                    |
| ------------- | ----------------------------------------------------------- |
| `raw`         | 应用收到的原始 argv。                                       |
| `invokedPath` | 用户实际调用的 command 与 handler 路径 token，保留 alias。  |
| `path`        | 选中 command 与 handler 的标准路径。                        |
| `inputs`      | 完成 command 与 handler 选择后剩余的位置 token。            |
| `options`     | 包含根、owner module 与 command option 值的冻结长名称 map。 |

该对象、嵌套数组和 `options` 快照都被冻结。已声明的 CLI 选项优先从 command 或 option provider 字段读取；需要合并视图时再使用 `args.options`。

## 注入运行时 Context

`Context` 是内置 DI 值。可以按类型注入 command、module 和 provider，用于读取应用的 appName、当前 command、完整 `commands` 元数据、IO streams、cwd、取消 signal 与当前调用 exit code。

<CodeBlock code={contextCode} filename="src/commands/major.command.ts" lang="ts" />

应用需要指定进程结果时，将 `context.exitCode` 设置为 0 到 255 的整数。执行发生错误后，如果用户代码尚未指定，func 会默认设为 1。

`Context.io` 包含本次调用的 stdin、stdout 和 stderr。命令如何区分正常结果与诊断信息、为什么不应直接使用全局 `console`，以及如何测试输入输出，见[输入与输出](/zh-cn/input-output)。

## 注入已注册 provider

类 provider 使用 `@Injectable()`，并且必须在 command 的 owner module 中可见。普通依赖注册到 `providers`；携带 CLI 字段的 injectable class 注册到 `options`。

## 使用显式 token 与 provider 策略

class 类型可以直接作为 token。接口、字符串配置或需要替换的实现使用 `createToken<T>(description)` 创建稳定 token，再通过 `@Inject(token)` 指定依赖：

<CodeBlock code={tokenCode} filename="src/app.module.ts" lang="ts" />

`Module.providers` 接受四种形式：带 `@Injectable()` 的 class、`{ provide, useClass }`、`{ provide, useValue }` 和 `{ provide, useFactory, inject? }`。`useFactory` 可以异步返回结果；`inject` 中的依赖按数组顺序传给 factory。依赖缺失、不可见或形成环时属于定义错误，不会静默解析成 `undefined`。

Exception Filter 通过 `catch(exception, context)` 接收 `Exception` 与当前 `Context`；Filter 构造函数仍由 DI 管理，可以注入普通 providers。详见[错误与生命周期](/zh-cn/error-handler)。
