`func` 提供标准的静态命令与选项解析，但也允许用户读取命令参数对调用进行动态解析。

## 使用 Args 读取当前调用

`@Args()` 是只能用于 Command Handler 的参数。运行时在完成 Command 选择与解析后才会创建它。

你可以在应用引用这些值进行业务处理，但需要注意，这只是逃生窗口而非主要实现途径，过度的依赖动态解析 (特别是 `raw` 数据) 会失去类型保护与静态分析的优势。

<CodeBlock code={argsCode} filename="src/commands/config.command.ts" lang="ts" />

| 字段          | 包含内容                                                    |
| ------------- | ----------------------------------------------------------- |
| `raw`         | 应用收到的原始 argv。                                       |
| `invokedPath` | 用户实际调用的 Command 与 Handler 路径 token，保留 alias。  |
| `path`        | 选中 Command 与 Handler 的标准路径。                        |
| `inputs`      | 完成 Command 与 Handler 选择后剩余的位置 token。            |
| `options`     | 包含根、owner Module 与 Command option 值的冻结长名称 map。 |

该对象、嵌套数组和 `options` 快照都被冻结。

## 注入运行时 Context

`Context` 是内置 DI 值，你可以在命令、服务以及模块中注入使用。
用于读取应用的设置数据、完整的元数据、IO streams、cwd、取消 signal 与当前调用 exit code 等。

<CodeBlock code={contextCode} filename="src/commands/major.command.ts" lang="ts" />

应用需要指定进程结果时，将 `context.exitCode` 设置为 0 到 255 的整数。执行发生错误后，如果用户代码尚未指定，`func` 会默认设为 1。

`Context.io` 包含本次调用的 stdin、stdout 和 stderr。命令如何区分正常结果与诊断信息、以及如何测试输入输出，见 [输入与输出](/zh-cn/input-output)。
