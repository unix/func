func has two intentionally different parameter paths: `@Args()` supplies invocation data to a selected handler, while constructor and handler dependencies are resolved through DI.

## Read the selected invocation with Args

`@Args()` is valid only on a command handler parameter. The runtime creates it after command selection and option binding, which avoids partially initialized argument objects during application bootstrap.

<CodeBlock code={argsCode} filename="src/commands/config.command.ts" lang="ts" />

| Field         | What it contains                                                                 |
| ------------- | -------------------------------------------------------------------------------- |
| `raw`         | The original application argv.                                                   |
| `invokedPath` | The command and handler path tokens as invoked, including aliases.               |
| `path`        | The canonical selected command and handler path.                                 |
| `inputs`      | Remaining positional tokens after command and handler selection.                 |
| `options`     | A frozen long-name map containing root, owner-module, and command option values. |

The object and its nested arrays/maps are frozen. Read declared CLI options from command or option-provider fields when possible; use `args.options` when code needs a combined view.

## Inject runtime Context

`Context` is a built-in DI value. Inject it by type into commands, modules, and providers to access command metadata, IO streams, cwd, cancellation signal, and the invocation exit code.

<CodeBlock code={contextCode} filename="src/commands/major.command.ts" lang="ts" />

Set `context.exitCode` to an integer from 0 through 255 when application behavior needs a specific process result. func defaults it to 1 after an execution error unless user code has already selected a value.

`Context.io` contains stdin, stdout, and stderr for the current invocation. See [Input and Output](/input-output) for the English chapter placeholder; the complete chapter is currently available in [Chinese](/zh-cn/input-output).

## Inject registered providers

Class providers use `@Injectable()` and must be visible through the command's owner module. Register them in `providers`; register CLI-bearing injectable classes in `options`.

/>

Use `@Inject(token)` for interface-like or non-class tokens. Missing or invisible dependencies are definition errors; they do not resolve as `undefined`.

`Exception` and `ExceptionContext` are passed directly to command and module `onError(exception, context)` hooks rather than injected as transient parameters. See [Errors and Lifecycle](/error-handler).
