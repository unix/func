  '    }',
  '',

  '  }',
  '}',

func uses ordinary class methods for lifecycle and error handling. Commands and modules may implement `onInit`, `onError`, and `onDispose`; providers may implement `onInit` and `onDispose`. Declare the matching `OnInit`, `OnError`, or `OnDispose` interface so TypeScript verifies the hook signature at compile time. No extra catch or lifecycle decorators are required.

## Error families

| Family            | Meaning                         | Routing                                                                        |
| ----------------- | ------------------------------- | ------------------------------------------------------------------------------ |
| `F_SYSTEM`        | Invalid application definition  | Thrown immediately and never delivered to `onError`.                           |
| `F_RUNTIME`       | Application or dependency error | Routed through the selected command and module error chain.                    |
| `F_RUNTIME_PRINT` | User-correctable CLI input      | Uses the same chain, then prints to stderr unless `preventDefaultPrint()` ran. |

<Callout title="System errors are definition defects" variant="caution">

Fix duplicate tokens, invalid providers, missing handlers, and other `F_SYSTEM` failures in the application definition. They intentionally bypass user error hooks.

</Callout>

## Handle a selected command first

Define `onError(exception, context)` directly on the command when command-specific recovery or context is useful. The exception contains stable failure data; the context controls handling behavior for that invocation.

Returning normally means the error is handled and stops propagation. Throwing from `onError` replaces the current error and continues to the next module hook.

## Put application policy on modules

The error order is the selected command, its direct owner module, then the root application module. Imported modules between the owner and root are not implicit global interceptors.

<CodeBlock code={moduleErrorCode} filename="src/app.module.ts" lang="ts" />

Use the root module for truly application-wide formatting, logging, translation, or telemetry. Use a feature module when the policy belongs only to commands declared directly by that module.

`F_RUNTIME_PRINT` failures still use default stderr output after the hook chain. Call `preventDefaultPrint()` only when the hook has produced an alternative message.

## Use one cleanup hook

`onDispose(outcome)` replaces separate finish and completion concepts. It always runs for each activated managed instance and receives the same frozen outcome object.

<CodeBlock code={lifecycleCode} filename="src/app.module.ts" lang="ts" />

For success, the outcome contains `status`, `result`, and `exitCode`. For failure, it contains `status`, `error`, `handled`, and `exitCode`. Cleanup runs command → owner module → root module → providers, with providers disposed in reverse creation order. Disposal failures are aggregated and do not re-enter `onError`.
