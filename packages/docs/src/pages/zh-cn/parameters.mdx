func 有两条明确区分的参数路径：`@Args()` 向当前 handler 提供调用数据；构造函数和 handler 的依赖则通过 DI 解析。

## 使用 Args 读取当前调用

`@Args()` 只能用于 command handler 参数。运行时在完成 command 选择与 option 绑定后才创建它，避免应用启动阶段出现只初始化了一部分的参数对象。

<CodeBlock code={argsCode} filename="src/commands/config.command.ts" lang="ts" />

| 字段          | 包含内容                                                    |
| ------------- | ----------------------------------------------------------- |
| `raw`         | 应用收到的原始 argv。                                       |
| `invokedPath` | 用户实际调用的 command 与 handler 路径 token，保留 alias。  |
| `path`        | 选中 command 与 handler 的标准路径。                        |
| `inputs`      | 完成 command 与 handler 选择后剩余的位置 token。            |
| `options`     | 包含根、owner module 与 command option 值的冻结长名称 map。 |

该对象及其嵌套数组和 map 都被冻结。已声明的 CLI 选项优先从 command 或 option-provider 字段读取；需要合并视图时再使用 `args.options`。

## 注入运行时 Context

`Context` 是内置 DI 值。可以按类型注入 command、module 和 provider，用于读取 command 元数据、IO streams、cwd、取消 signal 与当前调用 exit code。

<CodeBlock code={contextCode} filename="src/commands/major.command.ts" lang="ts" />

应用需要指定进程结果时，将 `context.exitCode` 设置为 0 到 255 的整数。执行发生错误后，如果用户代码尚未指定，func 会默认设为 1。

## 注入已注册 provider

类 provider 使用 `@Injectable()`，并且必须在 command 的 owner module 中可见。普通依赖注册到 `providers`；携带 CLI 字段的 injectable class 注册到 `options`。

接口或非 class token 使用 `@Inject(token)`。依赖缺失或不可见属于定义错误，不会静默解析成 `undefined`。

`Exception` 与 `ExceptionContext` 会直接传给 command 和 module 的 `onError(exception, context)`，不通过临时参数注入。详见[错误与生命周期](/zh-cn/error-handler)。
