下面的三个任务分别用于创建项目、整理结构和补充测试。Agent 组件会将完整提示词发送给所选应用，你也可以复制提示词并按项目需求修改。

## 创建一个新的 func 项目

### 适合的情况

这个场景适合第一次使用 func 的开发者，也适合希望在现有 monorepo 中快速建立独立 CLI package 的团队。只需要在编码 Agent 中打开目标仓库，无需手动逐项检查 Node.js、包管理器或 workspace 配置。

### Agent 执行的操作

- 读取仓库指引，检查包管理器和目录结构。
- 将固定项目名 `func-example` 传给创建器，并安装所需依赖。
- 阅读生成源码并运行帮助处理器，确认 CLI 可以工作。

### 完成后的项目

仓库中会新增一个可以运行的 func 项目，同时得到一份报告，列出创建的文件、目录位置和实际验证结果。 该项目可以用于学习，也可以作为后续业务 CLI 的基础。

## 优化已有 func 项目结构

### 何时需要整理

这个场景面向已经维护 func 项目的开发者。当命令越来越多、处理器中混入大量业务逻辑，或源码与生成产物混在一起时， 可以让 Agent 在不改变 CLI 行为的前提下整理结构。

### Agent 如何整理

- 检查入口、模块注册、命令、服务、测试和输出目录之间的职责。
- 识别职责混杂的文件，并按业务职责重新组织项目。
- 修正文件移动影响的 import、注册和测试路径，并运行相关检查。

### 整理后的变化

用户调用 CLI 的方式和输出保持不变，但可执行入口更精简，命令与可复用服务的职责更清楚。后续增加功能、定位问题或把项目交给其他维护者时，需要理解和改动的范围会更小。

## 为命令补充测试用例

### 何时需要补充测试

这个场景适合正在增加命令、准备发布版本或完成结构调整的维护者。它关注你的 CLI 向使用者承诺的行为，而不是重新测试 func 框架内部实现，因此也适合作为团队合并代码前的回归保护。

### Agent 如何补充测试

- 对照现有命令和测试，找出用户可见行为中的覆盖缺口。
- 从可执行文件启动 CLI，覆盖命令名、别名、处理器路径、选项约束与失败行为。
- 断言退出行为，以及不会随机变化的 stdout 和 stderr，并运行最小相关测试集。

### 新增测试覆盖什么

新增测试会覆盖应用对外提供的 CLI 行为：用户如何调用、成功时看到什么，以及出错时如何退出。 重构或升级依赖后，这些测试能更早发现行为变化，也不会依赖容易变动的内部实现。
