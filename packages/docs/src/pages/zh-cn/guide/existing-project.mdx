推荐创建一个带独立 `package.json` 的新目录。CLI 可以导入 应用公开模块或共享 package，但它的运行时依赖、测试和生成 bundle 都留在宿主应用的 package 与构建流程之外。

## 推荐：创建独立 CLI package

<CodeBlock code={separateTree} filename="仓库结构" />

独立目录可以避免宿主 package 的应用 bundler 将命令文件和 CLI 专用依赖混入产物， CLI 也可以单独发布、设置版本、测试或移除。在 monorepo 中，应把新目录加入已有 workspace 配置，而不是把它安装进应用 package。

创建器会交互式询问目录名。在父目录中运行以下命令即可创建 CLI package：

<CodeBlock code={createCode} lang="shell" />

通过已有 workspace package 或明确对外开放的模块共享业务代码。不要为了获取某个服务而导入应用 bootstrap；bootstrap 经常会在 import 时启动服务器、连接数据库或注册进程事件。

## 备选：在现有 package 中隔离 func

当仓库无法增加 workspace，或 CLI 本来就是同一应用的私有接口时，也可以共用 package。 只安装运行时和开发工具，不替换应用已有 scripts：

### 为什么这不会启动宿主应用

func 装饰器只会把元数据附加到声明它的类；import 时不会解析参数或执行处理器。只有显式调用 `run(CliModule)` 调用。只要仅有 `src/cli/index.ts` 调用 `run`，并且宿主应用不导入这个入口，func 就不会替换应用运行时或 bootstrap。

命令可以安全导入没有副作用的共享业务模块。如果共享逻辑需要状态或其他协作者，应把它包装为 `@Service` 并注册到 CLI 模块，而不是在命令文件内初始化全局状态。
